## 1. SOP（標準作業手順書）データ構造仕様
HITMANクローンは、Excel（.xlsm/.xlsx）、CSV、および内部辞書からリリース手順書をパースして管理する。

### 1.1 ステップ・スキーマ
各手順ステップは以下の属性を持つ：
```python
{
    "step_id": "1-1",               # ステップ識別子 (例: 1-1, 2-1, T-1, T-2)
    "title": "事前確認: ディスク空き容量チェック", # ステップ名称
    "objective": "ルートパーティションの空き容量が20%以上あることを確認する", # 作業目的
    "command": "df -h /",          # 実行すべきターミナルコマンド
    "expected_check": "Use% が 80% 以下であること", # 期待される客観証跡
    "cautions": "80%以上の場合は即時作業中断しエスカレーション", # 注意事項
    "rollback_step": "R-1",        # エラー発生時のロールバック分岐先
}
```

## 2. 自律Wチェック判定エンジン仕様
作業者からの入力内容を客観的に検証し、以下の3パターンに自動分類する。

### 2.1 判定ルール
1. **自己申告遮断（REJECT）**:
   - 「完了しました」「できました」「成功です」など、ターミナルコマンドの生ログを含まない文章入力は自動的に差し戻す（自己申告はエビデンスとして不合格）。
2. **エラー検知（ERROR / ESCALATE）**:
   - ログ内に `error`, `failed`, `exception`, `timed out`, `denied` 等のキーワードが含まれる場合、エラー判定としエスカレーションゲートへ誘導する。
3. **合格承認（VERIFIED_APPROVED）**:
   - 指定コマンドの実行結果、バージョン番号、HTTPステータスコード、PASSED表示等が含まれている場合、Wチェック承認を発行し次ステップをアンロックする。

---

## 3. 分岐制御＆エスカレーションゲート仕様
- **正常系**: ステップを順番（1-1 → 1-2 → 2-1 ...）に進行。
- **異常系 / 想定外事象**:
  - 作業中断・上長協議モード（ペア作業）への切り替え。
  - ロールバック手順（R-1: バックアップ復元、R-2: DBロールバック）への自動分岐。
  - 協議結果の客観記録（GO / ROLLBACK / ABORT）を保存。

## 4. A2UI リッチカード表示仕様
Google ADK の A2UI コールバックを活用し、チャット画面に以下のUIカードを描画する：
- **SOP手順書カード (`SOPCard`)**: ステップ名、目的、ワンクリックコマンドコピーボタンを表示。
- **Wチェック判定カード (`VerdictCard`)**: 合格（緑バッジ）、差し戻し（黄警告）、エラー（赤アラート）を視覚的に表示。
- **最終評価レポートカード (`ReportCard`)**: 全ステップの所要時間、Before/After比較、成果物保全チェックリストを表示。
