# 社内障害ログの自動解析＆解決コマンド即答Slackボット: Project Brief (要件定義書)
- **エージェント名**: `log-analyzer-bot` (社内障害ログ自動解析＆解決コマンド即答Bot)
- **開発者**: IPP AI研修 受講生
- **解決する現場課題**: 
  本番・ステージング環境で障害やアラートが発生した際、膨大なスタックトレースやログの読解に時間がかかり、一次切り分けや復旧初動（ロールバック・再起動等）が遅延してしまう。エラーログをSlackに貼り付けるだけで、AIがスタックトレースとエラー原因を即座に特定し、安全な調査・復旧コマンド候補を直感的なA2UIカードで提示する。

## 1. コア機能・技術仕様
1. **使用モデル**: `gemini-3.8-flash`（エラー解析・コード推論）、フォールバック: `gemini-3.6-flash`
2. **自作関数ツール (Tools)**:
   - `analyze_stacktrace(log_content: str) -> dict`:
     貼り付けられたエラーログ・スタックトレースから、例外クラス、発生モジュール、エラー原因を抽出・分類するツール。
   - `recommend_fix_commands(error_type: str, service_name: str) -> dict`:
     障害の深刻度とエラー種別に応じた安全な一次切り分けコマンド（ログ抽出、コンテナ再起動、DBコネクション確認など）を生成するツール。

## 2. A2UI リッチカード表示仕様
- **障害分析サマリカード (`IncidentSummaryCard`)**:
  検知されたエラー重大度（CRITICAL / WARNING）、原因の要約、影響サービスを表示。
- **推奨復旧コマンドカード (`RecoveryCommandCard`)**:
  調査・復旧コマンドをワンクリックコピー可能なコードブロック形式で表示し、Wチェック確認用ステータス（「未実行」「確認済」）を保持。

## 3. 長期記憶 (Memory Bank) 活用方針
- **過去インシデント事例の保持**: 類似エラーの過去の対応履歴と恒久対応パッチの情報を保持し、再発時に過去の成功対応手順を即座に推薦。

## 4. 実行環境・成果物
- **実行フレームワーク**: Google ADK (Agent Development Kit 1.5.0) + Python 3.12
- **フロントエンド / 公開先**: FastAPI Proxy + Cloud Run (リージョン: `asia-northeast1`)
