## 1. 2026-09-30 実機完走テストの総括

受講生実機にてコースA（自作AIツール開発: `ipp-wbs-agent`）を T-1 から T-6 まで通しで完走。

### 実際に発生した決定的エラーログ

表面的には「合格」と判定されながら、外部公開された Cloud Run を開いてチャットを打つと即座にサーバーエラー（HTTP 500）でクラッシュし、会話すら成立しない状態であった。

## 2. 特定された4大欠陥と根本原因

| 欠陥 | 現象 | 根本原因 |
|:---|:---|:---|
| **欠陥1: APIキー欠落によるコンテナクラッシュ** | デプロイ先で `/chat` を叩くと HTTP 500 で即死する | Cloud Run デプロイ時、コンテナに `GEMINI_API_KEY`（または Vertex AI 認証情報）を注入する仕組みが抜け落ちていた。 |
| **欠陥2: Wチェック判定の形骸化（ごまかし判定）** | 壊れたサービスなのに「S+ランク合格」として通過した | T-5 の合格条件が「デプロイログに URL 文字列があるか」だけであり、実際にその URL にリクエストを送って AI が応答するかという実稼働ヘルスチェックを行っていなかった。 |
| **欠陥3: 企画と成果物の完全な落差** | 「カレンダー＆ガントチャート＆日記アプリ」を作ったはずが、汎用の黒いチャット画面1枚しか出ない | 研修スキル `build-agent-frontend` が固定のチャットUIテンプレートしか持っておらず、どんな企画であっても画一的なチャット画面がデプロイされる設計になっていた。 |
| **欠陥4: UIデザイン・スクロール位置の破綻** | 次ステップに進むとプロンプトが画面外に押し出され見失う。カードの内容も手打ちしないコマンドが目立って無意味 | ① 自動スクロール（`scrollTop = scrollHeight`）が最下部カードにフォーカスするため上部のプロンプトが見えなくなる。<br>② 従来のSOPコマンド手打ち画面を引きずっており、プロンプト中心のUIになっていない。<br>③ 待ち時間（15〜60秒）に進捗率（%）が出ずフリーズに見える。 |

## 3. 包括的修正プラン（4つのフェーズ）

### Phase 1: デプロイ＆実稼働ヘルスチェックの信頼性担保（最優先・必須）
1. **APIキー／クレデンシャルの自動注入**:
   - ~~`gcloud run deploy --set-env-vars GEMINI_API_KEY=...`~~ は採用しない（キーがデプロイログ・Cloud Run の設定画面に平文で残り、そのログを HITMAN に貼るため）。
   - **対応済み（2026-09-30）**: 新スキル `ipp-cloud-run-deploy` の `deploy.py` が、`.env` のキーを標準入力で Secret Manager に登録し、`--set-secrets` で参照だけを渡す。
2. **T-5 デプロイ判定の実稼働ヘルスチェック義務化**:
   - `verify_step_output("T-5", ...)` の判定ロジックを改修。
   - デプロイログから抽出した Service URL に対し、バックエンドから実際に `POST /chat` リクエスト（ヘルスチェック用テストメッセージ）を送信する。
   - **HTTP 200 かつ AI正常応答が確認できた場合のみ合格（VERIFIED_APPROVED）** とし、HTTP 500 や 404 が返る場合は **問答無用で不合格（FAILED）** として差し戻す。

### Phase 2: UI/UX の抜本的改善（コースA/B両対応）
1. **自動スクロール位置の適正化**:
   - メッセージ受信・ステップ進行時、画面最下部ではなく **「AntiGravity投入用プロンプト（コードブロック）」の最上部** にスムーズスクロールさせる。
2. **プロンプト中心のカードデザインへの刷新**:
   - 受講生が手動で打たない `cat ...` コマンドの主表示を廃止。
   - 「AntiGravity への指示（プロンプトコピーボタン）」「生成される成果物概要」「提出ログ貼り付け枠」を一体化したモダンなカードへ刷新（コースA・コースB共通）。
3. **応答待ち進捗率（プログレスバー）の導入**:
   - T-3（スモークテスト）や T-5（コンテナビルド・デプロイ）などの長時間処理時、進捗率（%）と現在フェーズ（「ビルド中…」「テスト検証中…」）を可視化するインジケーターを設置。
4. **コースA初期カード表記の洗練**:
   - 企画確定前は「企画相談・確定待ち」であることが一目でわかるプレースホルダーに改善。

### Phase 3: ステップ数の柔軟化（最大10ステップ対応）
1. **可変ステップSOPエンジンの設計**:
   - 現在の固定6ステップ（T-1〜T-6）から、受講生の企画規模に応じて柔軟にステップを増減できる設計にする（最大10ステップ）。
   - 【拡張ステップ例】:
     - T-7: RAG ナレッジベース構築 ＆ ドキュメント検索連携
     - T-8: Guardrails / セキュリティ・プロンプトインジェクション評価
     - T-9: CI/CD パイプライン構築（Cloud Build / GitHub Actions）
     - T-10: 本番監視・Observability（Cloud Trace / ログ集計）

### Phase 4: フロントエンド表現力の強化
1. **A2UI リッチコンポーネントの拡充**:
   - カレンダー、ガントチャート、タスクリストなど、受講生の企画に合わせたデータ可視化コンポーネントを `a2ui_utils.py` およびフロントエンドでサポートし、「ただの文字チャット」から「企画を実感できるリッチなAIツール」へと進化させる。

## 4. ステップ別 検証・確認項目チェックリスト（別Agent評価用）

次期エージェントおよび開発者は、以下のチェック項目に沿って実装と検証を行うこと。

### [共通基盤]
- [ ] 単体テスト（`cd hitman && uv run pytest tests/unit -q`）が **100% PASS** すること。
- [ ] 結合テスト（`cd hitman && uv run pytest tests/integration -q`）が **100% PASS** すること。
- [ ] `git status` が常に clean であり、不要な一時ファイルやログが残っていないこと。

### [ステップ T-1: 環境構築＆スキル同期]
- [ ] `mkdir ipp-agent-workspace` が正常に実行されること。
- [ ] リポジトリ直下の `.agents/skills/` に必要なスキル（11種類）が同期され、`/ipp-skill-check` で正常確認できること。
- [ ] HITMAN 提出時に `[skill:ipp-skill-check@v1]` の証跡が含まれ、合格承認（`VERIFIED_APPROVED`）されること。

### [ステップ T-2: 企画＆要件定義（Project Brief）]
- [ ] **コースA**: HITMAN チャットで壁打ちを行い、企画合意時に **HITMAN 側で完全な要件定義書（project_brief.md）ドラフトが生成されること**。
- [ ] **コースA**: HITMAN の回答末尾に、AntiGravity 投入用プロンプトが **必ず ```text のコードブロック形式で出力されること**。
- [ ] **コースA**: AntiGravity にプロンプトを投入した際、**再ヒアリング（二重質問）を行わず、即座に `project_brief.md` を保存して cat ログを出力すること**。
- [ ] **コースB**: `hitman_spec.md` の仕様書出力および提出ログが同様に正しく検証されること。
- [ ] 提出ログに `[skill:pick-your-agent-project@v1]` が含まれ、エージェント名の一致が確認されて合格承認されること。
- [ ] 合格後、自動的に T-3 の Nonce（確認コード: `T3-xxxxxx`）が発行されること。

### [ステップ T-3: ADK エージェントコア＆A2UI実装]
- [ ] Nonce を含めたスモークテスト（`ipp-agent-smoke-test`）が実際に実行されること。
- [ ] 単なる固定値を返すダミー実装ではなく、異なる2つの入力に対してツールが呼ばれ、結果が動的に変化することが検証されること。
- [ ] 提出ログに `[skill:ipp-agent-smoke-test@v1]` と Nonce が含まれ、合格承認されること。

### [ステップ T-4: pytest 単体テスト＆自律Wチェック]
- [ ] エージェントの単体テスト（`tests/test_agent.py`）が実行され、全件 PASS すること。
- [ ] テスト結果ログを HITMAN に提出し、合格承認されること。

### [ステップ T-5: Dockerコンテナ化＆Cloud Runデプロイ（最重要確認項目）]
- [ ] デプロイコマンドに `GEMINI_API_KEY`（またはサービスアカウント環境変数）が確実に渡されていること。
- [ ] デプロイ完了後、発行された Service URL に対し、**実際にブラウザまたは curl で `/chat` を叩いて HTTP 200 かつ AI正常応答が返ること（500/404が出ないこと）**。
- [ ] HITMAN の `verify_step_output` が、実稼働ヘルスチェックを行い、エラー時は差し戻し、正常応答時のみ合格承認すること。

### [ステップ T-6: 個人GitHub公開＆最終評価レポート発行]
- [ ] スキル `publish-to-github` により、受講生個人の GitHub へ正常にプッシュできること。
- [ ] 提出ログに GitHub URL が含まれ、HITMAN が最終評価レポート（S+ランク等）を発行すること。
- [ ] レポート内の成果物パス・エージェント名が、受講生の企画と動的に一致していること。
